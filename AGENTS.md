# AGENTS.md

## Purpose

This repository contains a FlutterFlow-generated Flutter app. Treat generated code as replaceable by future FlutterFlow exports.

## Safe Editing Rules

1. Prefer isolated custom code over edits inside generated widgets, models, navigation, or backend schema files.
2. Avoid modifying files under `lib/flutter_flow/`, `lib/backend/schema/`, page widgets generated by FlutterFlow, and generated auth files unless there is no safer option.
3. Before changing a generated file, first look for a safer alternative such as:
   - a new service in `lib/`
   - a helper/utility file in `lib/`
   - a wrapper around generated behavior
   - a Firebase-side fix such as rules or Cloud Functions
4. Keep business logic separate from UI code. Generated page widgets should stay thin whenever possible.
5. When a generated file must be edited, keep the diff minimal, document why, and avoid style-only churn.
6. Preserve FlutterFlow naming, imports, and route contracts unless a change is required for correctness.
7. Do not delete or broadly refactor generated code just to “clean it up”.
8. Re-check impacted flows after any auth or navigation change, especially sign in, sign up, redirect handling, and logout.

## Project-Specific Notes

- Current auth entry page: `lib/login/login_widget.dart`
- Current protected page: `lib/pages/dashboard/dashboard_widget.dart`
- Router/auth state wiring: `lib/flutter_flow/nav/nav.dart`
- Firebase auth helpers: `lib/auth/firebase_auth/`
- User profile creation currently happens in `lib/backend/backend.dart` via `maybeCreateUser`

## Recommended Change Strategy

1. Diagnose first, patch second.
2. Prefer one well-contained reliability fix at a time.
3. For auth/profile reliability, prefer introducing a dedicated custom auth/profile service instead of spreading logic across generated pages.
